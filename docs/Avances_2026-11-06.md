### Funcionalidad implementada

- Administración del banco con cuatro opciones y una sola respuesta correcta por pregunta.
- Creación de pruebas en borrador, selección y ordenamiento de entre 1 y 20 preguntas del mismo grado y asignatura, habilitación y cierre.
- Conservación del contenido de cada prueba habilitada, aunque posteriormente se edite el banco.
- Inicio de intentos individuales con identificador, token aleatorio y modalidad de acompañamiento.
- Entrega de preguntas al estudiante desde un servicio que excluye las claves y justificaciones.
- Validación del envío completo y almacenamiento conjunto de respuestas y resultado.
- Calificación con igual peso por pregunta y porcentaje redondeado a un decimal.
- Prevención de intentos duplicados por identificador dentro de una prueba y de respuestas duplicadas por reenvío.
- Consulta de intentos y respuestas desde el administrador, con filtros y acceso limitado a las pruebas del docente; el superusuario tiene acceso global.

Las operaciones de [`evaluacion/services.py`](../evaluacion/services.py) ya están conectadas a las pantallas de ingreso, preguntas, confirmación y prueba cerrada. La interfaz usa HTML y CSS locales, sin requerir internet ni JavaScript.

El estudiante entra con código e identificador, sin cuenta ni contraseña. Su intento se mantiene en la sesión del navegador; se exige responder todas las preguntas y se conserva la selección si el servidor detecta errores en el envío. Los formularios verifican CSRF, preguntas ajenas, opciones inválidas y páginas pertenecientes a otro intento. Al terminar se puede liberar la sesión para otro estudiante. Las respuestas no enviadas no se guardan al recargar la página.

### Reglas de datos y acceso

- Las migraciones crean las siete tablas del proyecto y las cuatro asignaturas. Se reutilizan las tablas de Django para usuarios, permisos, sesiones e historial administrativo.
- SQLite impide grados y asignaturas fuera del alcance, opciones repetidas, más de una clave correcta, preguntas u órdenes repetidos en una prueba, respuestas duplicadas y aciertos superiores al total.
- Antes de habilitar, el servidor verifica que haya entre 1 y 20 preguntas activas del mismo grado y materia, con las cuatro opciones y exactamente una correcta.
- La secuencia de estados es **Borrador → Abierta → Cerrada**. La selección de preguntas, el grado y la asignatura quedan bloqueados al habilitar. No hay reapertura.
- El cierre impide nuevos intentos y envíos pendientes. Conserva los resultados ya enviados.
- Una misma prueba admite distintos identificadores; cada identificador tiene un solo intento en esa prueba. Los identificadores admiten hasta 50 caracteres y se normalizan a mayúsculas, quitando espacios al inicio y al final.
- El código de acceso tiene diez caracteres y se genera automáticamente. El token interno del intento es distinto: se mantiene en la sesión y no se comparte con los estudiantes.
- Las claves y justificaciones no se entregan en el cuestionario. Las páginas del intento indican que no deben almacenarse en caché.
- El docente consulta sus pruebas y resultados; el superusuario puede verlos todos. El banco es compartido para las cuentas con permisos.
- Los resultados y respuestas son de consulta en el administrador. El borrado de pruebas habilitadas está desactivado allí y las relaciones protegen los registros vinculados.
- El envío guarda respuestas y resultado en una transacción. Reenviarlo conserva la primera calificación. Un intento pendiente muestra porcentaje **Pendiente**; uno enviado con cero aciertos muestra **0.0%**.

La fórmula es `aciertos / preguntas aplicadas × 100`, redondeada a un decimal. No se calcula una nota conjunta entre materias.

### Importación del banco

El importador lee las tablas del Word y verifica identificadores únicos, grados, materias, enunciados, cuatro opciones, claves válidas y 20 preguntas por cada uno de los 12 bancos. Conserva los textos y los símbolos originales. El prefijo `CN` de los identificadores se relaciona con Ciencias Naturales (`NAT`) sin cambiar el código de la pregunta.

Se conserva la procedencia y el componente declarado en el documento dentro de la referencia. El Word no contiene referencias precisas ni justificaciones completas por ítem: no se inventaron esos datos ni se añadió un reporte por competencias. Las guías específicas y la revisión docente siguen pendientes. El Word original no se modificó.

Repetir la importación no duplica preguntas coincidentes. Si encuentra una pregunta existente con diferente enunciado, grado, materia, opciones o clave, informa del conflicto y revierte toda la carga; no sobrescribe las correcciones del docente.

## 1. Obtener y preparar el proyecto

Las instrucciones siguientes son para Windows y PowerShell, desde la carpeta que contiene `manage.py`. Se comprobó el proyecto con Python 3.13.7. Se necesita Python 3.13 y, si se va a clonar, Git; VS Code es opcional. No hace falta instalar un servidor MySQL: SQLite viene con Python.

Si el equipo ya publicó estos cambios en el repositorio, clonar desde la carpeta donde se quiera guardar el proyecto:

```powershell
git clone https://github.com/LuciaVega-L/EduDiagnostico.git
cd EduDiagnostico
```

Si se recibe una carpeta con el código, abrirla directamente en VS Code y usar **Terminal → Nueva terminal**. La ruta local original es:

```powershell
cd C:\Users\User\Desktop\ProyRedesOficialOficial
```

No ejecutar ambas alternativas: elegir la que corresponda a la copia recibida. Confirmar que existen `manage.py`, `requirements.txt`, `evaluacion/` y el banco en `docs/`.

### Crear el entorno e instalar dependencias

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Si `python` no se reconoce pero se instaló el lanzador de Python, usar `py -3.13 -m venv .venv` para crear el entorno. Los siguientes comandos siguen usando `.\.venv\Scripts\python.exe`; no es necesario activar el entorno ni cambiar la política de ejecución de PowerShell.

Dependencias fijadas: Django 5.2.19, asgiref 3.13.0, sqlparse 0.6.1 y tzdata 2026.6. La versión de SQLite comprobada fue 3.50.4 y depende del intérprete. ## 4. Crear una prueba propia y obtener su código

1. Iniciar el servidor y abrir `/admin/`.
2. Ingresar con la cuenta docente o administradora.
3. Abrir **Pruebas → Añadir prueba**.
4. Escribir un título, por ejemplo `Diagnóstico de Matemáticas — ingreso a segundo`.
5. Seleccionar **grado de ingreso** y **asignatura**. Una prueba corresponde a una sola materia y grado.
6. En **Preguntas de la prueba**, añadir las filas necesarias. Buscar las preguntas por código o enunciado; elegir únicamente las del grado y la materia seleccionados.
7. Asignar órdenes únicos del 1 al 20, preferiblemente consecutivos. Se pueden incluir entre 1 y 20 preguntas, sin repetirlas.
8. Guardar. La prueba queda en **Borrador**, se asigna al usuario que la creó y se genera automáticamente un código de diez caracteres. No se escribe manualmente el código.
9. Volver a la lista **Pruebas**, marcar la casilla de la prueba y seleccionar la acción **Habilitar las pruebas seleccionadas**. Ejecutar la acción.
10. Confirmar que el estado cambió a **Abierta**. Si falta alguna opción, no hay una clave correcta o las preguntas no coinciden con el grado o materia, revisar el mensaje y corregir el borrador.
11. Copiar el código de la lista o del detalle y entregarlo a los estudiantes, junto con sus identificadores.

Todos los estudiantes de esa aplicación usan **el mismo código** y **un identificador diferente**: por ejemplo `EST-01`, `EST-02`, `EST-03` y `EST-04`. El estudiante no elige grado o materia al ingresar: estos ya están definidos por la prueba.

Para evaluar otra asignatura, crear otra prueba. Para repetir una aplicación con los mismos estudiantes, crear otra prueba con otro código. Una vez habilitada, la selección de preguntas queda fija; las correcciones del banco se reflejan en nuevas pruebas.

## 5. Responder como estudiante

1. Abrir la página principal `/` en el servidor correcto.
2. Introducir el código de una prueba abierta.
3. Introducir el identificador asignado por el docente. No usar nombres o documentos reales para las pruebas académicas.
4. Elegir la modalidad: sin acompañamiento, individual con docente y auxiliar, o grupo de hasta cuatro con docente y auxiliar. El acompañante puede agregar observaciones opcionales.
5. Pulsar **Comenzar**.
6. Seleccionar una opción en cada pregunta. Todas las preguntas aparecen en la misma página; se puede revisar o cambiar la selección antes de enviar.
7. Pulsar **Enviar mis respuestas**. Si falta una respuesta o existe un error, corregirlo y enviar otra vez.
8. Verificar el mensaje **Tus respuestas quedaron guardadas**. El resultado numérico queda disponible para el docente, no se muestra al estudiante.
9. Pulsar **Terminar y volver al inicio** antes de atender al siguiente estudiante en el mismo navegador.

El intento pertenece a la sesión del navegador. Abrir otra pestaña en el mismo perfil no crea una sesión independiente. Para probar estudiantes simultáneos, usar dispositivos o perfiles de navegador distintos; varias ventanas privadas del mismo navegador también pueden compartir sesión.

Si se vuelve al inicio con un intento pendiente, el sistema lleva nuevamente a esa prueba. Si se cierra o recarga el cuestionario, las selecciones sin enviar se pierden. Si se pierden las cookies o se cambia de navegador, no se puede recuperar el intento solo con el código e identificador; para una prueba técnica se debe coordinar un identificador nuevo o una aplicación nueva con el docente.

## 6. Consultar resultados y cerrar pruebas

1. Ingresar a `/admin/` con la cuenta responsable de la prueba o como superusuario.
2. Abrir **Intentos**.
3. Buscar por identificador, título o código de prueba; también se puede filtrar por grado, asignatura, acompañamiento y fecha de envío.
4. Revisar el total de preguntas, los aciertos, el porcentaje y las fechas de inicio y envío.
5. Abrir el intento para ver sus respuestas y el acompañamiento registrado. Un intento pendiente no es una prueba calificada con cero.
6. Cuando ya no se admitan respuestas, ir a **Pruebas**, marcar la prueba y ejecutar **Cerrar las pruebas seleccionadas**.

Cerrar una prueba impide que los estudiantes que aún están respondiendo envíen sus respuestas. Conviene confirmar que terminaron antes de cerrarla. Los resultados enviados permanecen disponibles. No hay reapertura, edición manual de calificaciones ni exportación implementada.

## 7. Administrar preguntas y otras cuentas docentes

### Revisar o añadir preguntas

1. En `/admin/`, abrir **Preguntas** y filtrar por grado y asignatura.
2. Abrir una pregunta existente o elegir **Añadir pregunta**.
3. Completar código único, materia, grado de ingreso, enunciado y referencia. Añadir justificación y guía de aplicación cuando estén disponibles.
4. Registrar exactamente las opciones **A, B, C y D**, con texto, y marcar una sola como correcta.
5. Mantener **Activa** para permitir su selección en nuevas pruebas y guardar.

El administrador permite cambiar la clave correcta y reordenar la selección de un borrador sin violar las restricciones de SQLite. Al editar opciones existentes, su letra se conserva. Desactivar una pregunta evita habilitar nuevas pruebas que la incluyan; las pruebas ya habilitadas conservan su copia del contenido.

### Crear una cuenta docente adicional

1. Entrar como superusuario y abrir **Usuarios → Añadir usuario**.
2. Definir usuario y contraseña, guardar y abrir la edición de permisos de esa cuenta.
3. Mantenerla **Activa** y marcar **Es staff**, para permitir el acceso al administrador. No necesita ser superusuario.
4. Asignar los permisos siguientes, directamente o mediante un grupo de Django, y guardar.

| Modelo de `evaluacion` | Permisos necesarios |
|---|---|
| Asignatura | Ver. |
| Pregunta y opción | Ver, añadir, cambiar y eliminar. |
| Prueba y pregunta de la prueba (`ItemPrueba`) | Ver, añadir, cambiar y eliminar. |
| Intento y respuesta | Ver. |

Los nombres de permisos pueden aparecer como `Can view`, `Can add`, `Can change` y `Can delete`. No se requieren permisos para administrar usuarios. Las restricciones de la aplicación siguen aplicándose aunque un docente tenga permiso general de eliminar: por ejemplo, no puede borrar pruebas habilitadas desde el administrador.

Cada docente crea sus propias pruebas. Una prueba creada por `admin` no aparece en la lista de un docente distinto; el banco sí es compartido. Para crear una práctica del nuevo docente, usar `preparar_demo --docente SU_USUARIO`.

## 8. Probar desde varios computadores o celulares

Esta es la preparación para la demostración pendiente de Redes. Para que todos compartan pruebas y resultados, **un solo computador actúa como servidor**. Los demás usan su navegador; no necesitan instalar Python ni copiar la base.

1. Conectar servidor y clientes a la misma red local.
2. En PowerShell del servidor ejecutar `ipconfig` e identificar la dirección IPv4 de la conexión activa. En el ejemplo siguiente se usa **`192.168.1.50`**; sustituirla por la dirección real.
3. En `edudiagnostico/settings.py`, reemplazar la lista vacía `ALLOWED_HOSTS` por los nombres y la IP del servidor, sin protocolo ni puerto:

```python
ALLOWED_HOSTS = ['localhost', '127.0.0.1', '192.168.1.50']
```

4. Iniciar el servidor escuchando en esa IP local:

```powershell
.\.venv\Scripts\python.exe manage.py runserver 192.168.1.50:8000
```
